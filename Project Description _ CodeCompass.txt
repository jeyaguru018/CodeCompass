CodeCompass — Your Codebase, Finally Understood
Turn any GitHub repo into a guided, intelligent onboarding experience
Problem
When a developer joins a new team, understanding the codebase takes weeks — sometimes months. There's no tool that reads an actual repository and explains it in human language. Developers either get a verbal walkthrough from a senior (who's now blocked), skim through hundreds of files blindly, or read outdated wikis that don't match the current code. The cost of slow onboarding is enormous — and nobody has solved it at the code-intelligence level yet.

How they win and how they lose
Where they win
Sourcegraph excels at code search. Copilot autocompletes inline. CodeSee draws basic dependency graphs. Confluence stores whatever humans write.
Where they lose
None of them explain what the codebase actually does in plain English. None let you ask questions about a specific repo contextually. None surface bug hotspots or generate an onboarding path automatically.
Our project
CodeCompass takes a GitHub repo URL and transforms it into an interactive intelligence layer. It performs AST parsing across all source files, builds a module dependency graph, identifies the entry points and critical paths, and generates plain-English explanations at the file, module, and function level. A bug hotspot heatmap highlights files with the highest churn and complexity. A structured onboarding checklist tells a new developer exactly where to start, in what order, and why. Most powerfully — a RAG-based conversational interface lets you ask "what does the payment module do?" and get an answer grounded in the actual code of that repo, not generic knowledge.

How we overcome existing solutions
Sourcegraph helps you find code. We help you understand it. CodeSee draws a graph. We explain what every node in that graph does and how it connects to business logic. Copilot helps you write code. We help you understand the code already written. Nobody else is doing RAG over a user-provided repo with contextual Q&A — that's the technical moat.

AI features
RAG pipeline — repo files are chunked, embedded using a vector model, and stored in FAISS so the LLM can answer questions grounded in that specific codebase
AST-based code understanding — Python's AST module parses source files to extract function signatures, class hierarchies, and import relationships at a structural level
LLM-powered plain English summaries — GPT or Gemini generates human-readable explanations for each module and function from its parsed structure and surrounding context
Complexity scoring — cyclomatic complexity + git churn combined into a single hotspot score per file to surface risk areas automatically without manual code review

HR questions and your exact answers
HR asks
Why did you build this? Who needs it?
"India has 5.4 million software developers and that number is expected to reach 10 million by 2030. TCS alone onboards 40,000 freshers every year. Studies show it takes 3 to 6 months for a new developer to become productive in an unfamiliar codebase — and during that time they're blocked on seniors, reading outdated wikis, and guessing at how systems connect. CodeCompass cuts that ramp time by giving developers an intelligent, auto-generated map of any codebase they paste a GitHub link for."
HR asks
What makes this different from just reading code?
"Reading code tells you what individual lines do. CodeCompass tells you why modules exist, how they connect, which files are the highest risk, and where to start reading first — automatically. The RAG pipeline embeds the entire repo into a vector database, so when you ask 'where does the payment flow start' it retrieves the exact relevant files and generates a contextual answer grounded in that specific codebase — not generic knowledge."
HR asks
Has this been built before?
"Sourcegraph does code search. GitHub Copilot autocompletes. Neither explains what a codebase does end to end, generates an architecture diagram automatically, or lets you have a conversation about a specific repo. CodeSee draws basic dependency graphs but has no AI explanation layer. We're combining AST-based static analysis with RAG-based Q&A in a way that no student project and very few commercial tools have done."
HR asks
What's the technical complexity here?
"Four layers — AST parsing using Python's built-in AST module to extract function signatures and import relationships, dependency graph generation using NetworkX, RAG pipeline using LangChain and FAISS for vector search, and LLM-powered explanation generation using the Gemini API. The Java Spring Boot backend orchestrates all services and caches analysis results in PostgreSQL so repeated queries on the same repo are instant."
