STITCH MASTER PROMPT — CodeCompass

Design a complete, premium, production-grade web application called CodeCompass — a RAG-powered GitHub repository intelligence platform that turns any GitHub repo into a guided, conversational, visually explorable onboarding experience for developers. A user pastes a GitHub URL, the system parses the entire codebase (AST parsing, dependency graph, complexity/churn scoring, vector embeddings), and the user then explores that repository through an interactive architecture map, a bug-risk heatmap, an AI chat grounded in the actual code (RAG), and an auto-generated onboarding checklist. Design every screen listed below.

DESIGN LANGUAGE & VISUAL IDENTITY
This is a developer tool for engineers, not a business-ops dashboard — it must feel like something out of the Linear / Vercel / Raycast / Arc Browser school of design: dark-mode-first, precise, technical, quietly expensive. Nothing about it should look like a college project or a generic SaaS template. This is the second flagship project in a portfolio that already has a bright, indigo/emerald enterprise-dashboard-style product (ScheduleIQ) — CodeCompass must look, feel, and read as an entirely different design language: darker, more technical, more "developer-tool premium," with zero color or layout overlap with that first product.

Base mode: Dark mode as the primary, default experience (a light mode toggle exists in Settings but every screen below should be designed in dark mode).

Color palette (strictly different from indigo/emerald/amber/rose):
Background base: #0A0A0F (near-black, cool undertone, not pure black)
Surface / card background: #14141C with a 1px border in #24242F
Elevated surface (modals, drawers, popovers): #1B1B26
Primary accent: Electric Violet — #8B5CF6 (primary buttons, active nav states, the "Generate/Analyze" CTA, links)
Secondary accent: Cyan — #22D3EE (used for AI/chat elements, streaming text cursor, embeddings/vector-related UI, graph highlight edges)
Success / low-risk: #34D399 (emerald-mint, used only for hotspot heatmap low-risk and status-complete states — not used decoratively elsewhere)
Warning / medium-risk: #FBBF24
Danger / high-risk hotspot: #FB7185 (rose, reserved strictly for the bug-risk heatmap and error/failed states — this is the one functional color carried conceptually from risk-signaling convention, but the hex and saturation must feel distinct and cooler than a typical warning red)
Text primary: #F4F4F6
Text secondary: #9494A6
Text tertiary / muted: #5C5C6E
Border / divider: #24242F
Code block background: #0D0D13 with syntax highlighting in a One-Dark-inspired palette (keywords in violet #C084FC, strings in cyan-green #86EFAC, functions in cyan #67E8F9, comments in muted gray #5C5C6E)

Typography: Use "Inter" for all UI text (headers, labels, body). Use "JetBrains Mono" or "Fira Code" for anything code-related — file paths, function signatures, code blocks, terminal-style text, API endpoint labels. This UI-font / mono-font contrast is a signature detail — lean into it deliberately (e.g. repo names and file paths always render in mono, everything else in Inter).

Corner radius: Sharper and more technical than a typical consumer app — 8px for cards, 6px for buttons/inputs, 4px for tags/badges/pills, 3px for code chips. Avoid soft, bubbly corners.

Depth & texture: Mostly flat with very subtle 1px borders rather than heavy drop shadows (dark-mode UIs read as premium through contrast and hairline borders, not shadow blur). Use a soft violet or cyan glow (low-opacity box-shadow in the accent color) only on primary active/focused elements — the AI chat input, the "Analyze Repository" button, active graph nodes — to signal "this is where the intelligence lives." Use faint animated or gradient mesh backgrounds only on the Landing page hero and the Analysis Loading screen, never on data-dense screens.

Iconography: Thin-stroke (1.5px), geometric, technical icon style — think Lucide or Phosphor icons, not filled/rounded consumer icons.

Overall quality bar: Every screen must feel like a real, funded developer-tools startup shipped it — comparable to Vercel's dashboard, Linear's app, or Raycast's site. Use realistic data throughout: real-sounding GitHub repo names (e.g. "vercel/next.js", "facebook/react", "your-org/payment-service"), real file paths (src/server/middleware/auth.ts), realistic function names, and realistic commit messages. No lorem ipsum anywhere.

APPLICATION SCREENS TO DESIGN

SCREEN 1 — Landing Page
A dark, cinematic hero section. Large bold headline: "Your codebase, finally understood." Subheadline: "Paste a GitHub URL. Get an architecture map, a bug-risk heatmap, and an AI that actually knows your code." Center-stage: a large input bar styled like a command palette / terminal input with a GitHub icon, placeholder text "github.com/your-org/your-repo", and a violet "Analyze Repository" button with a subtle glow and a small spark/pulse icon. Behind the hero, a faint animated-looking dependency graph made of thin cyan/violet lines and nodes fading into the dark background (decorative, low opacity, technical texture — not literal illustration). Below the fold: a 3-step "How it works" section (Paste → Parse → Explore) with small mono-font code-style icons, then a feature grid of the 4 core capabilities (Architecture Map, Repo Chat, Bug Heatmap, Onboarding Checklist) each as a dark card with a violet or cyan icon, a headline, and one line of description. End with a "Trusted by developers exploring 1,200+ repositories" strip in muted text.

SCREEN 2 — Auth Page
Split layout, but inverted in feeling from a typical SaaS: left side is a dark panel with a large, elegant animated-looking node graph illustration (thin lines connecting glowing dots in violet and cyan) and the tagline "Understand any codebase in under 60 seconds." Right side is the auth card on the #14141C surface: a prominent "Continue with GitHub" button (dark, GitHub mark icon, subtle hover glow) as the primary option since GitHub OAuth is the primary auth method, a thin divider with "or continue with email," then email/password fields with mono-font input styling, a Sign In / Create Account toggle, and a small "Forgot password?" link. Keep this screen restrained and confident — it should look like a tool built by someone who codes, not a marketing-heavy signup page.

SCREEN 3 — My Repositories Dashboard
Top bar: CodeCompass logo/wordmark left (in mono font, small violet accent glyph), a command-palette-style search input center ("Search repositories... ⌘K" styling), notification bell, user avatar with dropdown right.
Below the top bar: a prominent "Analyze New Repository" input bar (same command-input style as the landing page but more compact) pinned near the top of the page.
Main content: a responsive grid of repository cards (3 columns desktop). Each card shows: repo owner/name in mono font with a small language-color dot, a one-line AI-generated summary, a row of stat chips (file count, function count, hotspot count in amber/rose if >0), a language breakdown as a thin horizontal multi-color bar, last analyzed timestamp, and status badge (COMPLETED in emerald, PENDING with a pulsing amber dot, FAILED in rose with a small retry icon). Include one card showing a repo currently analyzing (amber pulsing badge + inline progress percentage) and one showing a failed analysis (rose badge + "Retry" button) so both states are demonstrated. Each card has "Open Workspace" as the primary action and a small overflow menu (Re-analyze, Delete) as secondary.
Empty state (for when no repos exist yet): centered illustration of a faint node graph, headline "No repositories yet," and the same Analyze input restated as a call to action.

SCREEN 4 — Repository Analysis Loading Screen
A focused, almost terminal-like full-screen experience — this should feel exciting to watch, like a build pipeline running. Center: the repo name being analyzed in large mono font. Below it, a vertical checklist of the 7 pipeline stages (Cloning, Parsing, Building Graph, Generating Embeddings, Summarizing, Generating Onboarding Path, Complete) — each stage shown as a row with an icon that animates from a pending outline state, to an active pulsing violet/cyan state with a live sub-label (e.g. "Running AST parsing across 214 files..."), to a completed state with an emerald checkmark. A slim overall progress bar at the top in a violet-to-cyan gradient. Below the checklist, show a small live-updating counter grid (Files parsed: 142/214, Functions found: 891, Dependencies mapped: 1,204) that increments as if streaming. Include a subtle "Cancel Analysis" text link at the bottom, understated, not a prominent button.

SCREEN 5 — Workspace Shell (Overview Tab)
This is the core application shell used across all workspace tabs. Left sidebar (icon + label, collapsible): Overview, Architecture Map, Repo Chat, Onboarding, Explorer, Settings — plus the repo name/owner pinned at the top of the sidebar in mono font with a small back-arrow to the dashboard. Top bar inside the workspace: breadcrumb (Repositories / owner/repo-name), a "Re-analyze" icon button, and user avatar.
Overview tab content: a hero card with the AI-generated whole-repository summary in a larger, readable serif-adjacent or clean Inter paragraph (this is the one place body text can breathe more), framed with a thin violet left border like a quote callout. Below it, a 4-stat KPI row (Files, Functions, Hotspots, Documentation Coverage %) each as a minimal stat card with a large mono-font number. Below that, a two-column row: left — a donut/ring chart of language breakdown with a legend; right — an "Onboarding Progress" mini card showing a progress ring (e.g. 3/9 steps complete) with a "Continue Onboarding" button. Bottom section: "Recent Activity" showing the last few chat questions asked and files viewed, as a simple timeline list.

SCREEN 6 — Architecture Map Tab
The most visually impressive screen — treat it like the centerpiece. Full-canvas interactive force-directed graph (D3-style) filling most of the viewport, dark canvas background, nodes as small rounded rectangles or circles color-coded by module_type (entry_point in violet, api_layer in cyan, business_logic in a soft blue-white, data_layer in a muted teal, utility in gray), connected by thin curved edges that glow faintly cyan on hover/selection. Larger nodes for higher centrality/importance files. A floating toolbar (top-left, glassmorphic dark panel) with: a "Module View / Function View" toggle, a "Heatmap Mode" toggle switch (when on, nodes recolor entirely by hotspot_score using the emerald → amber → rose scale with a small legend), a zoom/fit-to-screen control, and a search-within-graph input.
Right-side drawer (slides in on node click): file path in mono font at the top, module type badge, complexity and hotspot scores as small horizontal meter bars, AI-generated file summary paragraph, last 3 commits list (message + relative timestamp), and two buttons — "Ask AI about this file" (cyan, links to chat) and "Open in Explorer" (outline style).
Show the graph mid-interaction: one node selected with its drawer open, heatmap mode toggled on so 3-4 nodes glow rose/amber as visible hotspots among the mostly-emerald/neutral graph.

SCREEN 7 — Repo Chat Tab (RAG-Powered)
A focused two-column layout: left is a slim session list (past conversations, mono-font titles auto-generated from first question, "+ New Chat" button at top). Right is the main chat panel: message bubbles with clear user/assistant distinction — user messages right-aligned in a violet-tinted surface, AI messages left-aligned on the base dark surface with a small CodeCompass glyph avatar. AI responses should visually demonstrate: inline code snippets in mono font with syntax highlighting, and citation chips below the response text (small pill-shaped tags like "auth/middleware.ts:45–62" in cyan mono font, clickable-looking) proving the answer is grounded in real code. Show one AI message mid-stream with a subtle blinking cyan cursor at the end of the text to convey the token-streaming SSE experience. Below the message thread, show a row of 3-4 "Suggested Question" pills (e.g. "Where does authentication start?", "What does the payment module do?"). At the bottom, the chat input bar: a rounded dark input with a small "@" or file icon to attach file context, and a violet send button with a glow when active. If a file/function was pre-loaded as context (from "Ask AI about this file"), show a small removable context chip above the input showing the file path.

SCREEN 8 — Onboarding Checklist Tab
A vertical ordered checklist styled like a guided reading path / changelog. Each step is a numbered card (large mono-font step number in violet) containing: the file path, an estimated reading time chip ("~8 min"), the AI-generated one-sentence reason this file matters, a "Mark as Read" checkbox/button that visibly glows emerald and the card dims to 60% opacity when completed, and a "View in Explorer" link. Show a mix of states — a few completed (dimmed, checked), one active/current (subtly highlighted with a violet left border), and the rest pending. At the top, an overall progress bar ("3 of 9 steps complete") with a percentage.

SCREEN 9 — File / Function Explorer Tab
Classic three-pane IDE-like layout but restyled premium-dark. Left pane: collapsible file tree (folder/file icons, mono font, indentation guides as thin vertical lines) with hotspot files showing a small rose dot indicator next to the filename. Center pane: syntax-highlighted code viewer (using the One-Dark-inspired palette described above) with line numbers in muted gray, and small violet sparkle icons in the gutter next to lines where a function begins (hover/click opens an AI explanation popover). Top of the code viewer: an AI summary banner in a thin violet-bordered callout box above the code. Right pane (optional/collapsible): function list for the open file, each as a small row with function name, parameter count, and complexity score badge. Include an "Ask AI about this file" button pinned near the top of the code viewer.

SCREEN 10 — Settings Tab
Simple, calm settings page split into sections: Account (avatar, name, email, plan badge — Free/Pro/Team), Connected Accounts (GitHub connection status with a "Disconnect" button and the connected GitHub username shown in mono font), Appearance (Light/Dark theme toggle pill, shown defaulting to Dark), Usage (a progress bar showing AI tokens used this month vs. plan limit), and Danger Zone (Delete Repository actions listed per repo, and Delete Account, both in a subtly rose-bordered card to signal caution without being alarming).

RESPONSIVE DESIGN
Design mobile versions for Screen 3 (My Repositories Dashboard), Screen 6 (Architecture Map — becomes a simplified vertical list of files with hotspot indicators instead of a full graph, with a note/icon suggesting "View full graph on desktop"), and Screen 7 (Repo Chat — full-screen chat takes priority, session list becomes a slide-out drawer). On mobile, the left sidebar collapses into a bottom tab bar with icon-only navigation (Overview, Map, Chat, Onboarding, Explorer). All touch targets minimum 44px. Maintain the dark theme and mono/Inter font contrast on mobile exactly as desktop.

OVERALL FEELING TO ACHIEVE
Every screen should look like it belongs to a product built by someone who deeply respects developer tooling aesthetics — precise spacing, restrained color usage (violet and cyan as the only "personality" colors, everything else neutral dark/gray, with amber/rose reserved strictly for functional risk signaling), heavy use of monospace type for anything that is literally code or a path, and a general sense of quiet technical confidence rather than loud enterprise-dashboard energy. This must be immediately, visually distinguishable from a bright indigo/emerald business-operations product — CodeCompass should look like the kind of tool a senior engineer would actually want to use, not a tool built to impress a manager.
